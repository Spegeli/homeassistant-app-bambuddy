> [!NOTE]

### Added
- **Duplicate queued and printing jobs (#3441, requested and contributed by 0xCyberFortress in #3440)** — A **Duplicate** button on each queued or printing job, and a **Duplicate** action for the selected jobs, add another copy to the end of the queue: same file, plate, target, project, filament choices and print options. A copy for a specific printer keeps its slot picks; a copy for any printer of a model has its printer and slots chosen again. The scheduled time and the batch are not copied, nor a hold the scheduler put on the original for filament. Printer-card uploads whose file is removed once they print get no button. The API has `POST /queue/duplicate` for this.
- **Multi-colour slices use both nozzles on an H2D or X2D (#3224, contributed by drkostas in #3270)** — The slicer put every filament on one nozzle, so a dual-nozzle printer swapped filament at every colour change while the other nozzle stayed cold. Bambuddy now sends a filament map that moves one filament to the second nozzle when a spool of that material and colour is loaded there, read from the printer the file is for, or from the printers of that model you may use. A 3MF saved by Bambu Studio 2.x also gets the map in its plate settings, which Bambu Studio reads before the command line. If the slicer refuses the map, the slice runs again without it, and any doubt (one colour, nothing matching on the second nozzle, an H2C) leaves the slice as before. The slice API takes an optional `filament_map` too: extruder 1 or 2 for each filament.
- **Print notifications can name who sent the job (#3584, requested and contributed by abezukor in #3601)** — Print started, completed, failed and stopped notifications have two new template variables: `{submitted_by}`, the user who sent the job from the web UI or from a slicer signed in with their personal access code, and `{submitted_by_email}`, that user's email, so a webhook bridge can turn the user into a chat mention. Both are empty when nobody is known, such as a print started on the printer itself. The email is only filled while an admin turns on **Submitter's email in notifications** under Settings > Notifications (off by default): users who can edit templates and providers can't otherwise read user emails. Wiki updated.
- **A Connect slicer page for users without Settings access (#3602, requested by paulleonartcalvo)** — Personal slicer access codes are meant for every user, but they, the virtual printers and the CA certificate were only in Settings > Virtual Printer, which needs Settings access. A new Connect slicer page, from the account menu in the sidebar (the person icon, which now also holds Change password), shows a signed-in user their access code, the virtual printers they may send to with it, with address, serial number and model, where their files go and whether the slicer shows a printer's live status, and the CA certificate with its installer. It lists exactly the virtual printers the sign-in accepts the user's code for. Administrators can add instructions in markdown in Settings > Virtual Printer, e.g. "connect to the VPN first", and send users the page's link. The CA certificate and its installer can now be fetched by any signed-in user; they only hold the public certificate.
- **Personal access codes show who sent a file to a virtual printer (#1430)** — A slicer signs in to a printer with one access code, so a virtual printer never knew who sent a file: in a school or makerspace, queue jobs and files had no owner. With auth on, every user now has a personal access code, at the top of Settings > Virtual Printer (copy it, or make a new one, which retires the old). Entered in Bambu Studio or OrcaSlicer instead of the virtual printer's own code, it works on any virtual printer in File Manager, Review or Queue mode, and what that slicer sends is the user's: the File Manager file, the queue jobs (which wait for a reviewer when the user's jobs must) and, in Review mode, the pending upload, whose file stays the sender's when someone else approves it. Each sign-in checks the user's account is active, that they may upload to the File Manager (plus queue jobs in Queue mode) and, for a virtual printer with a target printer, that the printer is one of theirs and they may see it, so a change of permissions or a new code takes effect at once. Sending files is all a personal code allows: the slicer's commands to the target printer (stop, pause, G-code, AMS) go through only for users with the printer control permission, checked at every command. An upload waiting for review keeps its own copy, so a later file of the same name can't replace it. The virtual printer's own code keeps working as before, without an owner. Not for Proxy mode. The slicer's camera view through a virtual printer with a target printer works with a personal code too, for a user allowed to watch that printer's camera: the printer checks the camera's code itself, so the virtual printer now signs the slicer in there with the printer's own code, and on port 322 the slicer sees the virtual printer's certificate (the one it already trusts for MQTT and FTP) instead of the printer's. The virtual printer's FTP sign-in now refuses an address for a minute after five wrong codes, as its MQTT sign-in already did, and on both a good sign-in no longer resets the count.
- **A script adds the virtual printer certificate to the slicers** — Bambu Studio and OrcaSlicer only connect to a virtual printer whose certificate is in their printer.cer file, and every slicer update or reinstall puts the original file back, so the certificate had to be added by hand again. The **Slicer certificate** card under Settings > Virtual Printer now downloads a script for **Windows** or **Linux / macOS** with this Bambuddy's certificate already in it. It finds Bambu Studio and OrcaSlicer, adds the certificate, and keeps the original file next to it. It changes nothing where the certificate is already there, and it removes an older certificate of the same Bambuddy, which would otherwise stop the slicer from connecting. On Windows it is a double-click: it asks for administrator rights, and it installs a task that adds the certificate again at every start, at every sign-in and once an hour, so a slicer update no longer breaks the connection (`/uninstall` removes the task). On Linux and macOS it runs with bash, and is run again after a slicer update. Wiki updated.
- **A virtual printer can be an H3C (#3442, requested by mgera-git)** — Settings > Virtual Printer now offers the H3C as a model. Bambu Studio recognises a printer by its serial, so a virtual H3C gets one like a real H3C (32X...). A proxy virtual printer for an H3C takes the model from its target.
- **A smart plug's temperature auto-off can wait for the bed (#3464, requested by EmcetPL, contributed by Keybored02 in #3539)** — With **Turn Off Delay Mode** set to **Temp**, a plug turned off once the nozzle cooled, which takes a few minutes, while the bed stays hot much longer: a plug that powers the printer cut it before the print could be taken off a cool bed, and before the Bed Cooled notification was sent. Temp mode now has **Wait for: Nozzle / Bed**, and the bed has its own threshold (35 °C by default, the Bed Cooled notification's default). Existing plugs keep waiting for the nozzle.
- **Choose which notifications get the camera photo (#2877, requested by HappyPuppy21)** — **Attach Photo** on a notification provider sent the snapshot with every event that has one, so a channel that should show the finished print also got a photo at the start and at 25, 50 and 75 percent. With Attach Photo on, the provider's settings now list the photo events it sends, and unticking one sends that event without the photo. Every event keeps its photo until it is unticked, and the provider card names the events that go without one.
- **BIQU Panda Breath on the printer card (#1466, requested by embed-3d)** — A Panda Breath chamber heater with firmware 1.0.4 or later can connect to an MQTT broker, and Bambuddy now follows it there. Under **Settings > Network > MQTT Publishing**, turn on **BIQU Panda Breath**; it uses the broker set there, and lists each Panda Breath that reports with the printer it is bound to. The printer card of that printer gets a **Panda Breath** tile with the chamber temperature it reads and its target; clicking it turns the heater on or off, picks Auto, Always on or Drying, and sets a target from 0 to 60 °C. The tile stays on the card while the printer is switched off, since the heater keeps running. The device is matched by the printer serial number it reports, so it needs to be bound to its printer in its own web interface. Changes need the printer control permission for that printer. Not tested on a real device yet. Wiki updated.
- **Limit which filaments a group may print with (#3522, requested and contributed by paulleonartcalvo in #3567)** — A group can now be limited to some filaments, as it can to some printers (#1727). In the group editor, **Limit filaments** under **Filament access** turns it on, with rules that either **Block these filaments** or **Allow only these filaments**. A rule names a material type (PETG, matched exactly, so PETG-CF is a different one) or a slicer filament ID (GFG03 for Bambu PETG Matte, the ID an AMS slot reports). A member may use a filament if any of their limited groups allows it; a user in no limited group, an admin, and every user with auth off are not limited. Queueing a file that needs a filament the user may not use is refused with the filament named. The print dialog says so before submitting, greys out the slots the group can't use and never picks one automatically. The queue never sends a job to a slot holding such a filament: it picks another slot, or holds the job with the reason on its row and starts it once the rules or the loaded spools allow it. That covers jobs from every source, including webhooks, pipelines and virtual printers, and "Print anyway" does not bypass it. Wiki updated.
- **Every user can choose the interface language (#3623, requested by balin77)** — The language picker was only in Settings > General, which needs Settings access, and it also changed the language of the whole install. A user without Settings access, such as a helper who only manages spools, could not switch the interface to their language. The account menu in the sidebar (the person icon) now has a **Language** picker; with authentication off, a globe icon in the sidebar footer opens it. It changes the language of this browser only, needs no permission and never changes the install-wide setting. The picker in Settings > General is now called **SpoolBuddy display language**, which is what it sets; it still switches the interface of the browser it is changed in.
- **Optionally run queued jobs whose filament is loaded first, with a maximum wait (#3587, requested and contributed by balin77 in #3627)** — A job whose filament was not on its printer (wrong colour or type, or not enough left on the spool) was staged and waited for someone to press Start, and a printer could stand idle while jobs behind it would have fitted. **Settings > Workflow > Queue & Dispatch > Loaded Filament First** now skips such a job instead: jobs behind it that fit run first, the queue order stays as it is, and the job starts by itself once its filament is loaded. Its row reads "Waiting for filament: … · priority in N h". After the **Maximum wait** (48 hours by default, counted from when the job was queued or its scheduled start; empty for no limit) the job gets priority: its printer (for an "Any model" job, the first idle printer in the configured printer order) is kept free for it, and the Job Waiting notification is sent once; without a limit it is sent once when the job starts waiting. A printer behind an auto-on smart plug is not switched on for a job whose filament its last-known trays don't have. **Print Anyway**, staged jobs and the plate-clear confirmation behave as before. Off by default, so nothing changes until it is switched on; queue rows now show the filament-wait reasons translated.
- **Unload all AMS 3H slots at once on the H3C (#3531, requested by Korazu)** — The H3C's touchscreen has an Unload All, but Bambuddy could only unload one slot at a time. The AMS 3H card header now has an **Unload all** button: it sends the same single command the touchscreen sends, listing every slot whose filament is in its PrintTool, and the printer unloads them one after another. It only shows while a slot is loaded and asks to confirm first, since the filament has to be pulled back out of the AMS 3H by hand when the printer asks.
- **A charging policy: print charges can include energy and printer wear (#3581, requested and contributed by paulleonartcalvo)** — With billing on, a print was charged for its filament only, although Bambuddy also works out its energy (from the smart plug) and its printer wear (#694), so the charge did not match the cost shown on the print. **Print Charges**, under Settings > General > Cost Tracking, now sets it for completed prints and for failed or cancelled ones separately: each can add **Energy Cost** and **Wear Cost**, and the **Filament charge** of a print that did not finish can be the amount used (as before), the full print, or not charged. The charge stays one transaction, and its description lists what it is made of, e.g. `Print charge: Benchy (filament 1.20 + energy 0.08 + wear 0.25)`. Energy and wear are charged whenever they are switched on for the print's outcome, also when its filament costs nothing (free spools, a failed print whose filament is not charged); with nothing to charge, no transaction is written, as before. Energy is read from the plug a few seconds after the print ends, so a charge that includes it is written then; if the plug cannot be read, or the reading does not come from the plug read at the print's start, the print is charged without energy and the description says so. So is a print that ended while its printer was offline: its end is noticed at the reconnect, and the plug's reading then holds everything since. A charge waiting for its energy survives a restart and is written at the next start, by the policy in force when the print ended, and without energy if it had not been read yet; whatever deletes its print log entry or archive in the meantime (the purge, deleting its printer or its user with their archives, and a merge included) writes it first, and one whose archive is gone all the same sends the billing-failed alert and releases its reservation. The filament in a charge is the print's own price at the spools it prints with (#3580), also when the charge waits for its energy or is written at the next start, and a print that did not finish is charged by its **Filament charge** setting from that price; a print on spools priced 0 is charged its energy and wear only. The Print Log's cost of a print stays its filament cost, with its energy and wear beside it as before. Budget checks and reservations still cover the filament estimate only. With nothing changed in the policy, charges are exactly as before. Wiki updated.
- **An AMS backup switch on a multi-filament print is shared out between the spools (#3650, requested and contributed by Eifel-Joe in #3653)** — When AMS Filament Backup switched to another spool mid-print, only a single-filament print shared the grams out between the two spools (#957, #1793). On a print with several filaments the whole amount went to the spool that ran out, and the backup spool was charged nothing. The built-in inventory and Spoolman now find the switch in the printer's tray log, as the one load of a tray that no filament of the print is mapped to, and share that filament's grams out between its spools: by the per-layer G-code when the file has it, by layer otherwise, and for a cancelled or failed print up to the layer it stopped at. The other filaments are charged as before. When the log does not fit a backup switch (a filament fed from the external spool, a tray two filaments share, a backup tray of another material or colour, a filament going back and forth between two trays), or the mapping was not known when the print started, the print is charged by its mapping, as before. Wiki updated.
- **Project labels for the bag or box of finished parts (#3655, requested and contributed by loidolt)** — Open **Label** from the project header or a project's card menu to print a quantity, an order or bag note, and a QR code back to the project. The project name, due date and colour are included by default. Optional lines show the parent project, parts printed, last print date and project ID. The dialog supports the spool labels' stock, saved and custom sheets, starting positions, live preview and PDF or PNG output. With Projects: read, the API can print several bags or projects in one batch. Wiki updated.
- **Choose which spool an RFID tag belongs to (#3658, requested and contributed by loidolt)** — Built-in inventory now asks which spool you loaded when several untagged spools match and any has recorded usage. The prompt lists the matches with their used weight and notes. If all are unused, the oldest still gets the tag. You can also link an unassigned RFID slot from the printer card or move a tag to the correct spool from the slot or spool dialog. Moving a tag updates the slot for the rest of a running print. Usage already booked stays on the original spool.
- **Look up spools on 3D Filament Profiles, with store prices and a Reorder link (#2981, requested by apizz)** — Connect your 3D Filament Profiles account under **Settings > Filament**: Bambuddy shows a code, you approve it on 3dfilamentprofiles.com, and no API key has to be copied. Every user connects their own account, and a free account allows 100 lookups a month. In the spool form, enter a barcode (a USB barcode scanner works), a 3D Filament Profiles filament id or a link to a filament: the brand, material, type, colour, net and empty spool weight are filled in, and the slicer preset too when the spool has none. The spool is linked to that filament, so the form then shows its current store prices with a **Reorder** link for each region. Works the same in Spoolman mode. Syncing spools with 3D Filament Profiles comes later.
- **Add Spool starts with your last spool and lists the brand's colours and empty spools first (#3619, requested by balin77)** — Adding many colours of one product meant typing brand, material, preset, weights, location, cost, category and suppliers again for every spool. A new spool now starts with these values from the last spool created in this browser; colour, note, used weight, tag data, last dried and material number are not carried over, and **Clear** at the top of the form empties it. Edit and Copy are unchanged. The catalog colours now include the brand's product lines, so Polymaker + PLA lists the PolyTerra PLA colours, and **Show all colours** lists every colour of the brand. The empty-spool weight picker lists the brand's spools under **Suggested**.
- **A version group is one card in the File Manager (#3628, requested by balin77)** — Files grouped with **Group as versions** (one print sliced for several printer models) took a card, row and column entry per version. The File Manager now shows a group as one card or row in the grid, list and columns view: it shows the first version's thumbnail, the printer models and the number of versions, and **Show versions** lists each version with its own actions (print, download, remove from group). In the list and columns view they open in place; in the grid they open in a popover under the card (a bottom sheet on a phone), so the other cards never move. The group's menu has **Ungroup** and **Delete all versions**. A version that sits in another folder is listed with its folder name. Ticking a group selects its versions in this folder, so Move, Delete and Tag never reach into another folder, and printing a group, alone or among other selected files, queues one job with the versions as printer alternatives (#3462). A group the user can't fully see is shown as the plain files they can. The variant group endpoints now list only the members the caller may read, and changing a group needs ownership of all its active members unless the caller may update all files.
- **Filament override from the inventory, with a stock hint (#3590, requested by balin77)** — The filament override in the print dialog only offered filaments loaded in a printer, so a job could not be queued for a colour that was still on the shelf. With the built-in inventory, the override can now offer the shelf too: tick **Show inventory colours** in the dialog's Filament Override section, or turn it on under **Settings > Workflow > Inventory Colours in the Filament Override**. It is off by default, applies to the whole install, and changing it needs the permission to change settings. The inventory colours and the checkbox are shown to users who may read the inventory. With it on, the override lists **Loaded now** and **In inventory, not loaded**: every type and colour in stock that no printer has loaded, with how many spools and how much filament are left (for example "2 spools · 1.4 kg", or "none left in inventory"). Picking an inventory filament turns on **Force color match** for that slot, so the job waits until the spool is loaded, the job is saved under the colour name the inventory has for that spool, and the dialog warns when the inventory holds less than the job needs. A job waiting for a forced colour with none left says so in its waiting reason ("PLA (Earth Brown) – none left in inventory"), and the new **Filament Out of Stock** notification event (off by default) tells you; both only while the setting is on. For a job for any printer of a model the event goes to providers set to all printers, like Queue Job Waiting. With it off, the dialog and the waiting reasons are as before, and a job already saved with an inventory colour keeps it. In Spoolman mode the checkbox is hidden and the picker shows only the loaded filaments. Whatever the setting says, a job held on a printer for a filament that is not loaded now names the printer, and the colour by its name where the job knows it ("A1 Left needs PLA Earth Brown" instead of "Needs PLA #7D6556").
- **API keys in a header on the camera snapshot and stream routes (#3707, requested and contributed by Marceltov)** — A server-side integration had to mint a stream token and send it as `?token=` in the URL, where a reverse proxy's access log keeps it, so anyone who can read that log can watch the camera until the token expires. The camera snapshot, stream and plate-detection reference thumbnail routes now also accept an API key as `X-API-Key` or `Authorization: Bearer bb_...`, as the media routes already do. The key needs **Read Status** (camera:view) and only reaches the printers it is limited to; an open stream ends when the key is disabled, expires, or loses that access. A login token in the header is not accepted, and when a request carries both a `?token=` and a key, the token decides. `?token=` works as before. Wiki updated.
- **SpoolBuddy reads OpenTag3D, OpenSpool and FilaMan tags for Quick Add (#3657, requested and contributed by pleasantone)** — An unknown NTAG spool opened Quick Add as a blank PLA, even when its tag held the material, colour, brand and temperatures, and even when Bambuddy had written the tag itself. A SpoolBuddy client can now send the tag's data area with the scan (`ndef_hex` on `nfc/tag-scanned`), and Bambuddy decodes it the way it decodes a Bambu tag's blocks (#2685): OpenTag3D, in the v1 layout Bambuddy wrote before #3500 and the 2.x layout, OpenSpool, FilaMan System's tags with extended data, and FilaMan's own spool and manufacturer tags. Quick Add then starts from what the tag says. Fields a tag leaves out stay empty or take Quick Add's defaults. A tag with a colour but no colour name (OpenSpool and FilaMan have no field for one) gets the name from the colour catalogue when a row of the tag's brand has exactly that colour, narrowed by the product line or material where the brand has several; rows that still disagree give no name rather than a guess, and a colour near a catalogue row's but not equal to it gets none either. The Bambu rows only name Bambu Lab tags. Colours you add to the Color Catalog count too. JSON records written by NFC Tools on iOS, which stores the MIME type as an external type, are read too. The scan's response now also returns the decoded `tag_data` and a `tag_format` (`opentag3d`, `openspool`, `filaman_system`, `filaman`, `filaman_mfr`, `bambu`, or `blank` for an NTAG with no message), so a client with its own screen can show them; until now the prefill only went to the kiosk. A FilaMan tag that only links a spool already registered in Spoolman is recognised but not prefilled, so Quick Add doesn't duplicate that spool, and the 175-275 °C range FilaMan writes when Spoolman has no temperatures is ignored. A tag in a format Bambuddy doesn't know is scanned as before, with one log line naming its record type. The Raspberry Pi daemon doesn't send the data area yet; ESPoolBuddy clients will. Wiki updated.
### Changed
- **Virtual printer cards start collapsed** — Settings > Virtual Printer opened every virtual printer's card with all its settings, so a few of them filled the page. Each card now shows only its header (name, mode, model, status) until it is clicked.
- **Virtual printers put uploads in the File Manager, not the archive** — An archive is a print that happened, but a virtual printer archived every file the slicer sent, in Archive, Review and Queue mode, before it ever printed. Uploads now go to the File Manager, and the archive gets the file when it prints, like any other File Manager print. **Archive** mode is now **File Manager** mode; virtual printers set to it switch over on upgrade, and archives they created before stay as they are. Each virtual printer card has a **File Manager folder** (by default a shared top-level folder named **Virtual Printer**; external folders can't be picked). The same file sent again under the same name into that folder doesn't make a second copy. **Review** mode stays: pending uploads now wait at the top of the File Manager page (the sidebar badge moved there too), and **Add to File Manager** stores them in the virtual printer's folder with their tags, notes and project (approving now needs the `library:upload` permission as well as `queue:create`, since it adds a file); the panel is translated now too. **Queue** mode stores the file and queues it from there, and a new switch, **Remove from File Manager once it prints** (off by default), takes it out of the File Manager when its print starts. With **Save AMS mapping** on, the slicer's tray pick still reaches the archive for reprints: the queue job keeps it until the print creates the archive, shows the saved-mapping badge meanwhile, and offers it under **Mapping** when edited. The virtual printer's archive-name setting (file name or 3MF title) applies to the archive made when the print starts. Wiki updated.
- **A queue virtual printer shows where its jobs go, and its target can be cleared** — In Print Queue mode a virtual printer without a target printer sends each job to the next free printer of its model, but the card's target list only said "Select a printer...", and once a printer was picked there was no way back. The first entry now reads **Any available [model]** and switches the virtual printer back to that, and a line under the list says where the jobs go. The access code stays the same, so the slicer stays bound. In the other server modes the entry reads **None**; proxy mode still needs a printer. Wiki updated.
- **The "job assigned" notification is sent once the job can start on its printer (#3522, contributed by paulleonartcalvo in #3567)** — An "Any model" job was announced as assigned the moment the queue picked a printer for it, before the queue had mapped its filaments to that printer's slots. The notification now follows that step. For every user, also one without filament rules, a job that fails right after the assignment because its filaments can't be mapped on that printer is no longer announced as assigned first; it sends the failure only. A job held by its creator's filament rules is given back to the pool without the notification, so it is not sent again on every pass of the queue.
- **With billing on, a reprint is charged at the spools it prints with (#3580, requested and contributed by paulleonartcalvo)** — An archive keeps the cost of its first print (#1378), and every later print of it was charged from that figure: a reprint on a spool bought at another price, or mapped to another spool in the print dialog, was billed at the old price. Each print is now priced when it starts, from its plate's planned filament at the spools mapped for it, and charged from that; a failed or cancelled print is charged its share of it, as before. The archive card still shows the first print's cost. A first print of one plate of a multi-plate file is now charged from that plate's own figure too, not from the whole file's cost scaled to the plate's share. A print with no spool mapping to price it from is charged from the archive's cost, as before. The budget a queued reprint reserves is priced the same way when the queue item has a spool mapping, so the reservation and the charge agree; without one it is the archive's cost until the queue maps the job's filaments at dispatch and prices it again. In Spoolman mode the reservation finds a spool as the charge does: by its RFID tag first, then by its slot assignment. In the built-in inventory a spool priced 0 counts as free, so a print only on such spools is charged nothing and reserves nothing; in Spoolman a price of 0 means the spool has no price, and it is charged at the default rate. A built-in spool with no price is not free: it is charged at the default rate, and with a default rate of 0 it does not price the print, which is then charged from the archive's cost. A completed print with no measured cost is logged in the Print Log at what it was charged. A print whose price was not worked out by the time it ends (it failed within seconds, or Bambuddy restarted) is priced at its end. With billing off, none of this is worked out and Spoolman is not asked for prices when a job is queued.
### Fixed
- **Imported filament profiles missing from a spool's per-nozzle preset picker (#3731, reported by theomichail)** — The spool's **Printers** tab read the printer model out of a preset's name and only understood a size written as `0.2 nozzle`. A profile named `BBL A1 0.2mm nozzle` or `BBL A1 0.2` therefore seemed to belong to another printer and was left out, even though its `compatible_printers` named the A1 0.2. An imported profile with `compatible_printers` is now offered on exactly the model and nozzle rows that list names. Names may write the size as `0.2`, `0.2mm` or `0.2mm nozzle`, with a trailing tag such as `(Custom)`; this also fixes the Configure AMS Slot list and the slice dialog's name fallback. **Auto-match** recognises these sizes too.
- **User and group management permissions no longer look delegable (#3729)** — Creating, editing and deleting users and groups has required admin status since v0.2.4.7, so that no one can make themselves admin. The group editor still offered these six permissions to every group, though, and a non-admin who held them saw **Add user** and **Add group** buttons that ended in "Requires admin role". The group editor now marks these permissions as taking effect only for administrators, and non-admins no longer see the buttons. Viewing users and groups can still be granted to any group.
- **A camera stream that won't stop is logged again** — When Bambuddy kills a stalled camera stream and ffmpeg still doesn't exit within a few seconds, it gives up waiting and logs an error. That error was never written: the check that ignores an ffmpeg that has already exited also caught the timeout. Found by CodeQL.
- **A spool picked per printer is kept when a forced-colour job goes to several printers (#3711, reported by NeighborGeek)** — A virtual printer with **Force color match** on queues each job asking for exactly the colour it was sliced with. Editing such a job, selecting several specific printers and picking a spool for each under **Custom mapping** saved every job still asking for the sliced colour next to the picked spool, so the queue dropped the pick and held the job with "Waiting for PLA #004000". A spool picked for a printer now replaces the sliced colour on that printer's job, as it already did with one printer selected. A printer whose spool was left as auto-filled still waits for the sliced colour.

- **A drying cycle cut off by a power loss no longer switches the plug off again when the printer comes back (#3662, reported by worried-networking)** — When the printer lost power mid-cycle, its first report after power came back read the drying countdown as 0. Against the minutes Bambuddy last saw, that looked like a finished cycle: the log blamed the firmware for ending it early, and Auto Off After Drying switched the plug off again a few minutes after power-on. The first report after the printer was out of sight (connection lost, or its plug switched off by Bambuddy) now decides how the cycle ended: if its countdown could not have run out in that time, or Bambuddy switched the plug off under it, the cycle counts as cut off. Nothing acts on it as a finished cycle, and the log says so. - **Auto-off no longer cuts the printer's power during an AMS drying cycle (#3660, reported by worried-networking)** — A print that finished while an AMS was drying scheduled the smart plug's auto-off as usual, and switching the plug off stopped the drying cycle, with hours of drying left. The same happened with a queue job's "Power off printer when done", and with two AMS units on one printer when one finished drying while the other still dried. An auto-off now waits while any AMS on the printer dries, also a cycle started on the printer or in Bambu Handy, and switches the plug off once the last cycle has ended: after the drying delay when Auto Off After Drying is on, otherwise after the plug's own delay. A print that starts meanwhile still keeps the plug on. An auto-off resumed after a restart waits for the printer's first report before it decides. Wiki updated.
- **A job waiting for a spool that is too short can be printed anyway (#3659, reported by balin77)** — With **Loaded Filament First** on (#3587), a job whose spool holds too little filament waits for filament instead of being staged, so its row had no Start button and there was no way to say "print anyway" short of deleting the job and queueing it again on one printer. Once confirmed, the job no longer waits for the spool: a job on a specific printer starts there once the printer is free, and an "any model" job goes to the first free printer that has its filament loaded. - **A backup no longer damages a live SQLite database, and a backup and a restore no longer run into each other (#3309, reported and contributed by Thomansky in #3372)** — The backup copied the running SQLite database as a plain file. On Linux closing that copy dropped the app's own file locks, and the database could then lose its write-ahead log and stop opening ("file is not a database") shortly after a scheduled backup. It is now copied with SQLite's backup API, which reads one consistent snapshot while Bambuddy keeps writing. Only one backup or restore runs at a time: a download or a restore started while a backup runs is refused with a message saying so, and a scheduled backup waits for a running one. A local backup gets its final name only once the ZIP is whole, so the backup list never offers a half-written one, and a backup that could not copy some files says so instead of reporting success. The PostgreSQL export no longer holds up the server either, and a backup cancelled at shutdown leaves no staging folder or partial ZIP behind.
- **A cancelled print after a backup spool switch is shared out by the layers actually printed (#3652, reported and contributed by Eifel-Joe in #3654)** — When AMS Filament Backup switched to another spool mid-print and the print was then cancelled or failed, the two spools got different shares in the two inventories. With per-layer G-code, Spoolman ignored it and shared the grams out by layer count, while the built-in inventory followed how much each part of the print actually fed. Both now share a cancelled print out up to the layer it stopped at, and follow the G-code when the file has it, so they charge the same.

### Security
- **Slicer sidecar images: dependency updates and no build tools in the image (#3530, reported and fixed by pleasantone)** — The sidecars' package lock dated from April, so every image rebuild shipped the same published advisories. All fixes are within the declared version ranges:
  - **Reachable through the sidecar API:** multer 2.5.0, which handles every upload (GHSA-72gw-mp4g-v24j, GHSA-wc9g-mqfw-jrwm, GHSA-535w-7cp7-47q4, GHSA-q7qp-rjg7-q26m, GHSA-3p4h-7m6x-2hcm, GHSA-qvfw-j98x-7q72: denial of service and an upload size check that could be bypassed); body-parser 2.4.0 (GHSA-27r3-jxmh-p828, GHSA-v422-hmwv-36x6), path-to-regexp 8.4.2 (GHSA-j3q9-mxjg-w52f, GHSA-27v5-c462-wpq7) and qs (GHSA-q8mj-m7cp-5q26, GHSA-x5fp-wj9c-mxmx, GHSA-4mjr-xmp4-gh2g, GHSA-6pq8-jhm2-2vcw), which parse every request: denial of service.
  - **Present, not reachable:** proxy-addr 2.0.8 (GHSA-jqcg-44mw-7w3h): the sidecar does not trust proxy headers, so the address check it fixes is never used. lodash 4.18.1 (GHSA-r5fr-rjxr-66jc, GHSA-f23m-r3pf-42rh) and brace-expansion are only used inside archiver when it packs the result file, never with request data.
  - **Not shipped any more:** the images carried the whole build and test toolchain (vitest, vite, eslint, typescript and their dependencies, including vitest GHSA-5xrq-8626-4rwp, vite, postcss, picomatch, nanoid, flatted, source-map-js, js-yaml and form-data advisories), plus npm, npx and corepack. None of it ran in the sidecar. The images now contain only what the API runs: 170 packages instead of 285.
  - **Left over:** two moderate advisories in glob and minimatch under archiver 7 (GHSA-3g3m-2fjr-6pw4, GHSA-g3hv-75wg-m249). The fix needs archiver 8, a major version. archiver uses them only to pack the result file, with no request data.
